# VR 回传流畅度优化 · versionCode 9

## 升级与使用

1. 退出旧 PC 工厂程序，等待约 15 秒，让它托管的旧回传服务结束。
2. 保留新版 PC 文件夹的全部内容，运行 `EngineFactoryPC.exe`。
3. 用 `adb install -r EngineFactoryVR.apk` 覆盖安装头显应用：同包名、同签名，versionCode 9 / 1.0.20261014.0。重新进入工厂应用。
4. 两端位于可互通的局域网；收到有效左眼图像后仍自动展开 PC 小窗。不需要重新推送连接配置，SimPy 服务保持原配置及运行方式。

若 PC 提示“旧服务限速”，可能有手动启动的旧回传脚本仍占用 8011。请自行停止该旧视频服务后重开新 PC 程序；不要停止 SimPy 8000 服务。程序会兼容旧视频服务并遵守其 8 FPS 目标，不会强制结束其他程序。

本机本次检查：8011 的旧手动服务是 **PID 30504**，可在任务管理器“详细信息”按 PID 找到并结束这一进程。PID 仅适用于此次检查；换电脑或重启后应重新核对端口归属。关闭旧 PC、停止旧视频服务后，新 PC 会自动启动包内20 FPS服务。

## 本版变化

- 异步采集目标 **20 FPS**，PC 下载最新帧轮询上限 30 次/秒。按完整处理耗时扣除等待，不补发积压帧。
- 主线程把 GPU 读回数据复制到会话独占数组，后台线程编码 JPEG；每个会话只处理一个在途帧，保留最高 640×480、JPEG 质量 50 和原宽高比。
- 服务 `target_fps=20`，上传硬限流最高 30 FPS，为时间抖动留余量；256 KiB 上限、单帧存储及观看租期不变。遇到限流退避，网络失败退避。
- 无异步 GPU 支持或异步读回失败时自动回落同步读回，目标 2 FPS，并明确显示回退原因。
- 原自动连接、配对、收起、V 键、本地漫游、休眠及重连继续使用。

## 看诊断

PC 小窗底部 FPS 为一秒统计的实际接收帧率；“目标20”只是目标，不代表设备已经达到20帧。
“VR 连接”菜单显示头显报告的读回、编码、上传毫秒及单帧 KiB。读回、上传耗时包含管线等待，不能当成纯 GPU 或网络传输时间。
小窗“帧龄约 … ms（估计）”仍只是服务驻留和下行估计，不包括整个头显采集、编码、上行链路。

日志在各端 Unity 持久数据目录。头显原右手 B 导航诊断、长按右手 A 的连接设置继续使用。
PC 自带 `VRMirrorService`，视频 TCP 8011、发现 UDP 8012；首次 Windows 局域网访问提示应允许。

## 验证与真机验收

测试使用独立端口、只读仿真 fixture 和明确标记的编辑器采集图像。编辑器/独立 EXE 的 FPS 不能代表 Rhino X Pro 的读回性能。
检查包含：真实后台 JPEG 编码解码与图像颜色、发送节流、GPU 读回管线、同步回退、旧服务协商、显示统计、停止/销毁资源、过期画面隐藏、自动显示及收起、三种分辨率、导航及工位几何。

本机结果：独立 HTTP 上传/下载约 **18.6 FPS**、100 帧无重试；最终 PC EXE 接收测试样本 **15.0／18.4／16.7／17.9 FPS**，339 帧上传无错误，第一帧自动展开及退出清理通过。后台 JPEG 编码约1毫秒（640×360编辑器参考）。编辑器完整 GPU 采集管线约9 FPS，受编辑器渲染、读回和调度限制，未把它当作20 FPS真机验收。
PC 和 APK 构建均无错误，APK 的包名、versionCode 9、签名、ARM64、网络权限及仅含 VR 场景检查通过。PC 构建保留原模型碰撞网格、弃用接口及缺失 Scene Volume 脚本的已有警告，未扩展本轮修改范围。

真机请在入口、中部、设备密集处及转头移动时各检查一次。关闭回传与开启回传分别连续运行 15 分钟，记录实际接收 FPS、头显渲染帧率、CPU/GPU 帧时间、掉帧及内存。目标正常局域网下稳定 15～20 FPS；头显渲染帧率下降超过 10% 时不视为性能验收通过。
工程已有 `vr_performance_v4.json` 性能记录；CPU/GPU 数据不可用时明确记为不可用，不以零代替。对比测试需重新启动应用以分别采样。

目前未连接头显，只报告编辑器、独立包和资源检查结果；真实左眼方向与流畅度仍需真机验收。
旧 PC 及 versionCode 8 APK 保留。H.264/WebRTC 和厂商投屏接收 SDK 不在本版接入。
