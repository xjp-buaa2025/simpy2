# PT6A 29工位工厂预览

本次交付为独立布局和运输演示。PC、VR共用70×48m布局、29个实体工位、3个缓存区和50m主链龙门吊。保留原79工序仿真入口、服务和旧安装包；本预览不连接排产、回放、共享时钟或布局发布接口。

## 使用

- PC：运行新版目录中的 `EngineFactoryPC.exe`，保留整个目录。顶部切换俯视、斜视、漫游、工位特写和屋顶。点击地面/设备选工位，或使用上一/下一工位按钮。
- PC视角：右键拖动旋转，滚轮缩放，中键平移。漫游使用WASD、Shift加速、右键看向，Esc返回全景。
- 运输演示默认暂停。播放/暂停、复位及1/5/10倍速均只操作本地演示；空格播放/暂停，R复位。一个完整循环约40分钟演示时间，在10倍速下约4分钟。
- VR：保留既有定位、左杆瞬移、右杆转向/高度控制。右手独立射线配合扳机操作演示面板，A键收起或在面前呼出；B键继续用于导航诊断。
- 两端读同一布局，各自控制本地演示。不会同步修改正式排产时间或生成实际产量。
- Unity编辑器打开 `Assets/Scenes/PT6A29_PC.unity` 或 `PT6A29_VR.unity` 后按Play查看；场景按统一布局数据生成，停止Play后保留入口和配置。

## 布局与物流

尺寸采用用户第二张图。图纸坐标左上角为零点，u向右、v向下；Unity世界坐标为X=u−35、Z=24−v，Y=0是地面顶面。净高8m。各工位长宽、0.5m分隔缝以及4m/5m通道均按尺寸链布置。

核心链为G01→G02→G03→G04→M05→TC01→CL01。中央五站共用连续轨道吊车，试车及清洗位于右侧。AGV执行预制件配送和后段整机转运；同一工位内不产生运输任务。

ST-A暂存整机，ST-B缓存燃油组件，ST-C缓存滑油、冷却和线束。所有缓存数字均为本地演示状态。

本轮有137件设备实例，按工位配置工作台、支架、检测台、柜体、部件交接台、试车及清洗设施。重复模型使用共享网格及LOD，工作台数量不代表仿真容量。专用装置为工厂布局展示模型，未作为工艺或吊装轨迹认证依据。

实际整机模型的运输占地大于空车。道路按空车/小件1.10m、整机载荷1.30m保守旋转包络验证，均包含0.25m余量；M05、ST-A、TC01、CL01交接点距区域边界调整为1.45m，其余默认1.20m。工位矩形和通道尺寸没有改变。

## 后续接入仿真

数据主文件为 `data/factory_layout/pt6a29/layout.json`，工步来源索引为同目录 `process_sources.json`。Unity的嵌入副本和StreamingAssets由生成工具复制，禁止分别手改两端文件。

布局区分稳定的 `station_id` 和各个 `instance_id`，包含矩形、设备局部坐标、作业槽位、交接点、通道、物料交接关系、龙门吊及演示时间线。正式工步以后通过 `workstation_id` 绑定这29个工位，缓存区不作为加工资源。

来源索引保留原工作表名、行号、工步号、人员、行为及原始时长。它包含29个工作表、674条来源记录；能够处理不间断连字符、Excel控制字符及C01表第8行表头。它不是已经完成的可执行工艺DAG。

旧79工序均保留待映射状态。原流程中的滑油/燃油聚合节点不能推测性地分摊到新工位；下一轮须按工作簿建立正式工序、时序协同及齐套关系。

## 维护与检查

生成数据：`python tools/pt6a29_layout.py`。Unity入口为 `PT6A29_PC.unity` 和 `PT6A29_VR.unity`，独立脚本以PT6A29开头。编辑器请求工具为 `tools/pt6a29_delivery.py`；原布局/构建工具未修改。

自动检查包括工位尺寸与重叠、来源索引、21,000余个路径采样、设备落地及区域包含、暂停与倍速、确定性定位、四段吊运、整机载荷包络、完成停止和复位。交付检查文件记录PC实机程序、编辑器和头显三种证据类别。

本次检查时ADB未连接头显。VR编辑器检查和APK构建不代表头显双目、定位或帧时间已实测。
