# 按需人员与无目标上限的评估口径

## 生效规则

- 所有运行均采用按需人员池，从空池开始；工位和设备具备开工条件后同步配齐班组，不等待人数。
- 空闲人员按累计工作时间、创建顺序复用。释放班组不会清除连续工作、疲劳或历史记录。
- 工序 `required_workers` 仍表示班组人数，决定人员记录和人分钟；不会自动缩短标准工时。
- 连续工作触发休息时保留原班组、释放物理资源，休息后重新申请设备和工位。每次作业尝试最多一次前置休息。
- 高负荷工序的后置休息结束后才完成节点并释放后继工序。返工仍释放资源后重新排队。
- 不再按目标产量截断投产。计划流水线沿用首工序半时长的投产节奏，串行完成一台补一台，能力评估按在制上限持续补投。
- 首工序零工时时使用流程中首个正标准工时的一半作为投产间隔，最低 0.01 分钟。整条流程标准工时均为零时拒绝持续生产。
- 评估期结束时，工作、休息与等待区间均截断到期末；未完成休息的产品不会提前计为完工。

## 配置和结果兼容

旧输入 `num_workers`、`target_output` 和工区 `dedicated_workers` 接受但忽略，包括旧方案导入。新配置不再序列化这些字段；前端比较签名同样忽略它们。历史结果的原始快照不改写。

旧达成率兼容字段返回 `null`，不能解释为 0% 或 100%。指标、评分和建议不再使用目标值，也不将虚拟人员作业率解释为缺员瓶颈。

新增结果信息：

| 字段 | 含义 |
| --- | --- |
| `evaluation_context.worker_supply_mode` | 固定为 `on_demand` |
| `evaluation_context.labor_minutes` | 工作区间长度 × 分配人数的累计值，包含期末部分工作 |
| `evaluation_context.peak_working_workers` | 同时处于正常工作、返工或期末未完成工作中的峰值人数，不含休息和等待 |
| `engine_completion_events` | 调度器记录的 `{engine_id, end_time}`，只包含真正完成的整机 |

`worker_stats` 保留个人工作、休息和疲劳数据，人数由实际分配产生，不再是配置容量。网页首页和产出概览使用峰值同时作业人数、累计人分钟。

## PC / VR 回放

继续使用 schema 3、原事件结构和 `worker_ids`。新回放不输出目标字段；客户端保留对历史字段的读取兼容，但新界面不再显示或使用目标。全线里程碑显示实际台数，单台工序保留进度。

发布器优先使用调度器的实际整机完成时刻；旧结果缺少此字段时保留历史推导路径。期末仍在作业或休息的人员可继续显示为未完成状态，不代表产品已完工。
