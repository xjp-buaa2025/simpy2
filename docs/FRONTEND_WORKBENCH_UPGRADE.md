# 网页工作台升级交付与验收记录

日期：2026-10-15。范围：原生 JavaScript、Canvas、Chart.js 4.4.1 前端。没有修改本轮的排产算法、接口契约或 PC/VR 播放时钟。

## 使用方式

1. 在“文件”菜单导入 CSV、载入方案 JSON 或加载 79 工位示例。
2. 流程编辑：单击工序在右侧编辑，右键工区打开两参数面板。选择工具拖动移动，Shift＋拖拽或连线工具创建依赖。独立按钮折叠工区、适应画布；布局和层级视图位于“视图”。
3. 工区仍使用“作业效率”“并行工位套数”，取消恢复原值，保存保留历史结果并标记待重算，“查看改善效果”沿用原有同条件比较。
4. 仿真设置中查看评估条件和基础库存，高级参数、休息规则折叠。运行前错误保留输入并就近显示。
5. 结果分析按产出、资源、人因与质量分组。点击资源编号可打开对应甘特视角。
6. 排产甘特切换产品、真实人员、设备与工位；支持工区、对象、事件筛选，日／周／全期、自定义分钟范围、按钮及 Ctrl＋滚轮缩放。普通滚轮纵向浏览。点击任务查看详情，点击行名称查看对象详情。
7. 有有效结果后进入“展示排产”。展示期间可分析和导出，退出恢复原页、筛选、时间范围、缩放、选择和滚动，工序及工区草稿保留。
8. “导出 PNG”打开实际图像预览，可通过“下载 PNG”保存。事件 CSV 可导出全部或当前筛选及时间范围内事件，保留原始数值。结果页“打印 / PDF”使用浏览器打印。

## 数据与实现

- `result_view.js`：历史结果适配与区间索引。评估上下文优先于原始请求；日历优先取 time_mapping，配置与流程来自结果快照。不会从当前编辑器补写历史记录。
- `gantt_view.js`：单一可见区 Canvas、引用归集、固定标签及表头、并行任务分轨、实际事件命中。区间查询包含从时间窗之前延续进来的长任务。Canvas 与命中统一逻辑坐标，支持 DPR。
- `workbench.js`：公共状态、展示恢复、结果分组、资源统计、工序右侧编辑与草稿保护。资源使用和等待分开统计；历史等待缺少受阻编号时明确说明无法完整分配到具体编号。
- `workbench.css`：深色顶栏、浅色工作区、统一控件与打印样式。工具箱偏好单独保存在 `assembly.ui.toolbox`，不写入方案业务配置。
- Chart.js 4.4.1 已放在 `frontend/vendor/`，通过已有 `/static` 挂载读取，保留上游版权说明。图标使用项目内 SVG，无运行时外部 CDN。
- JSON 载入先验证输入及结果事件，成功后统一刷新分析；不发布到 PC/VR。打开、筛选、缩放、选择及展示不调用仿真或同步接口。

## 浏览器验收

浏览器：Windows 10，Chrome/154.0.0.0（Codex 内置浏览器）。真实方案包含 79 工位、28,175 条事件、15 名真实人员；性能样本包含 100,000 条事件、200 名人员及 200 台独立编号设备，约 31 MB。性能样本通过本地方案文件载入，不请求仿真和结果发布。

| 场景 | 实测 |
|---|---:|
| 十万事件适配与建索引 | 87.1 ms |
| 十万事件视角归集／筛选 | 14.9 ms |
| 连续滚动／缩放期间可见区绘制最大值 | 3.6 ms |
| 180 帧滚动与缩放平均帧间隔 | 17.57 ms |
| 平均帧率 | 56.92 FPS |
| 帧间隔 P95 | 18.5 ms |
| 点击命中处理 | 0.2 ms |
| 展示与视角切换 | 20 次，Canvas 5 → 5 |
| 验收期间写请求 | 0 |

详见 `results/workbench_validation/browser-performance.json`。该浏览器测量使用 DPR 1.5，内嵌视口为 1265×650；DPR 1/2 的精确尺寸与命中另外由单元测试覆盖。结果读取与 JSON 解析不计入适配／绘制耗时；本次使用本地文件，没有结果网络下载，浏览器 JSON 解析阶段未单独计时。帧率为本机固定样本结果，不代表所有硬件。未执行浏览器堆快照或监听器数量的内存分析，持续切换检查记录了 Canvas 数量与恢复行为。
