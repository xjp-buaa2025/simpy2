# 工区两参数改善

在流程编辑页，右键工区标题、内部空白或所属工序，打开右侧属性面板。默认只需调整作业效率与并行工位套数，再点击“查看改善效果”。查看不修改模型，关闭面板保留画布位置和缩放。

## 两个参数

- **作业效率**：默认100%，支持100%～200%，提供100%、125%、150%、200%快捷按钮。实际作业时间＝原始抽样工时÷效率倍率。例如125%使30分钟变为24分钟。原始标准工时不被修改，返工作业同样提速；人员需求、设备绑定、工艺依赖、返工概率和休息时长继续生效。
- **并行工位套数**：默认1套，支持1～4套。2套表示保留原有资源，为本区每个实际使用的工位新增其基础并行名额，并自动配套新增人员和有限设备。新增资源只供本区使用，原公共池、专属分配和基础库存保持原值。

每新增一套，配套人员按各工位“基础容量×该工位工序最大人数需求”汇总；某种设备按实际使用该设备的工位基础容量汇总。同一工位多道工序使用同类设备时去重，普通无限工具不增加库存。这是完整配套的扩建估算，可能高于轮岗所需人数。面板实时展示预计新增数量。

“保存”只保存局部草稿；“取消修改”恢复已保存值；“查看改善效果”先校验保存，再评估。首次保存启用工区约束。已有人员分配、设备与具体工位配置、名称、工序绑定和等待分析均在高级设置中。

## 同条件改善评估

默认持续补投，使用有界在制队列。基准取最近一次同流程的成功能力方案；没有时，在当前基础配置上把所有工区的两个快捷参数复位为默认值。两次评估固定流程、日历、初始空线、随机种子、逐工序随机样本和在制上限。自动上限取两个方案有效工位并行名额总数的较大值、至少2台；参数配置中手填上限则遵守手填值。

条件完全相同的基准结果直接复用，否则自动重算。面板展示本区有效标准作业时间、本区完成套数、整线完成台数。非瓶颈改善可能使整线产量不变，系统如实展示，不预设归因。参数调整期间保留上次有效结果；评估失败时保留结果并显示错误。

基准不发布至PC/VR；候选成功后沿用原同步路径。PC/VR工位容量读取有效容量，设备外形不复制。载入方案JSON只恢复配置与历史结果，不主动发布。原生客户端仍需使用包含工区回放支持的版本。

## 接口及兼容

`capacity_model.areas`增加`efficiency_multiplier`和`resource_sets`，默认均为1；`evaluation.sampling_scheme`支持`legacy`（默认）和`paired_v1`。稳定取样由种子、产品号、工序号、执行次数和取样类型决定。`POST /api/simulation/run`增加`publish_to_clients`，默认true；自动基准设置为false。

快照区分原有资源、新增数量和有效总量，并记录有效工位容量、评估条件及两参数。方案JSON支持往返；缺少新字段的旧方案按默认值运行。计划仿真保留原投产规则，仍可在参数配置中选择。

## 验证命令

后端：`python -m pytest -q`。前端：`node --test tests/test_area_editor.cjs`。覆盖效率换算、完整资源包、原有与新增资源联合原子分配、资源归还、休息返工、非瓶颈无增产、基准不发布、失败保留结果、随机样本、旧格式兼容和79工位回放容量。
