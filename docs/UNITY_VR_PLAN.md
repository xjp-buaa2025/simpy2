# 工厂第一视角窗口与燧光头显接入方案

> 2026-10-03 更新：已实现共享工厂、PC/VR 入口、PC 主控共享时钟及 VR 专用简化。VR 当前范围为观看，不提供手柄漫游；本文件后续部署章节保留为规划。现行使用与验收说明见 [PC 与 VR 观看端](UNITY_PC_VR_CLIENTS.md)。

## 已完成：PC 第一视角窗口

HelloUnity 场景运行后，左下角显示同一工厂的第一视角窗口。主全景、窗口里的工位状态、AGV 和完工发动机都来自同一个 SimPyReplayRuntime，时间轴、暂停、速度及网页结果切换共用，无需复制一份工厂或重算仿真。

- 点击窗口画面进入漫游；WASD 水平移动。
- 按住右键在窗口内转向；Q/E 也可以左右转向。
- Shift 加速，R 复位，Esc 或点击窗口外退出漫游输入。
- V 隐藏/重新打开窗口；右上角“隐藏 V”按钮也可以隐藏。
- 视高默认 1.7 米，行走速度默认 5 米/秒，独立于仿真速度。此阶段限制工厂边界，尚未加入设备碰撞。
- 附近 28 米以内工位显示世界空间名称、状态和进度条；全景仍使用原有浮动标签。
- 摄像机输出 960×540 RenderTexture 到 UI 窗口，只渲染本机场景，不传输视频。

源代码：`C:/AllUnityProjects/MainProject/MainProject/Assets/Scripts/SimPyReplayFirstPerson.cs`。

## 现有 XR 组件保留

场景保留 `XR Origin (VR)`、Camera Offset、Main Camera、跟踪组件和交互组件。项目现有 Ximmerse UnityXR SDK 1.8.3，XR 设置为 Android + Ximmerse XR Loader。新增桌面摄像机不驱动 XR Origin，不替换头显跟踪摄像机；检测到本机 XRDisplaySubsystem 运行时，保留 XR 相机输出及控制器射线。

本机 XR 启动后，小窗口预留为跟随 XR 摄像机位置和朝向的单目场景预览。它并不是头显真实图像的镜像，也不意味着 PC 已收到独立头显的跟踪数据。没有设备接入，本次只验证了编辑器内的桌面窗口；头显立体渲染、定位、手柄与性能需要真机验证。

## 建议的部署方式：同一工程、两个构建

针对当前 Ximmerse Android XR 配置，建议原生头显应用方式：

| 部分 | 运行位置 | 作用 |
|---|---|---|
| SimPy 服务与网页 | PC | 算排产并发布同一份结果 |
| Windows Unity 程序 | PC | 工厂全景、统计、演示控制、观察窗口 |
| Android APK | 燧光头显 | 头部跟踪、双目显示、第一视角巡游 |

是同一个 Unity 工程输出 Windows 构建目录和 APK，不是维护两套不同的工厂。PC 端需要保留 EXE 周围的数据文件，不能只复制一个 EXE。SDK 官方说明 RhinoX Pro 是 Android 设备，原生部署需要 Android Build Support 和 APK：[燧光官方入门指南](https://doc.ximmerse.com/sdkconf/unityxrsdk/chapter_3.html)。具体头显型号仍需确认；现有 SDK 不代表所有燧光型号都兼容。

连接关系：PC SimPy 服务 → PC 全景客户端 / 头显客户端。头显通过局域网访问 PC 的服务地址，如 `http://<PC局域网IP>:8000/api/simulation/unity/replay.json`。APK 中不能继续使用 `127.0.0.1`，它指的是头显自己。

算法仍只在 PC 运行；两端读取同一 sim_id 的结果。已有功能同步的是排产结果，不是跨设备的播放时钟。要让 PC 和头显在同一时刻显示同样的工位状态，需要下一阶段增加由 PC 控制的统一时间轴，广播 sim_id、播放/暂停、速度、当前仿真分钟和时间戳，头显按同一时钟播放并在重新连接时校准。不能仅让两个客户端各自自增时间。

## PC 窗口显示头显视角的两种方式

1. **同步位置与朝向，在 PC 重绘场景**：头显发送位置、旋转和统一仿真时间，PC 在当前窗口重绘。数据量小，适合监看巡游；不同端画质及 MR 现实背景可能不同，不是逐像素一致。
2. **接收头显实际投屏视频**：设备端投屏或采集编码视频，PC 解码后填入窗口，能显示头显输出的画面。是否包含真实环境背景、画面延迟和嵌入 Unity 的接口，要根据设备和投屏能力确认。[Rhino X Pro 官方产品页](https://www.ximmerse.com/RhinoXPro)列出 Miracast MR 投屏能力，不能由此推定所有型号或 PC 嵌入接口都已支持。

建议先做位置/朝向 + 统一时间轴同步。如果目标是演示给别人看“佩戴者眼前的实际画面”，再接入视频投屏。

## 真机阶段还需做的工作

- 确认具体燧光型号、SDK/固件和 VR/MR 显示模式。
- 当前 manifest 的多人 SDK 引用 `D:/MRMR/multiusersdk-unityxr-master/multiusersdk-unityxr-master`，本机未找到该目录。编辑器目前仍能运行；正式打包前需恢复此本地依赖或按实际使用情况处理引用。
- APK 配置 PC 服务地址，验证同一局域网的数据访问。
- 统一时间轴与头显姿态同步。
- 按头显性能评估 CAD 模型复杂度；头显构建关闭桌面全景与预览等额外渲染。
- 工厂范围较大，需要控制器传送或摇杆移动；桌面的 WASD 不会自动变成 VR 操作。
- 世界空间 UI 的清晰度、定位原点、地面高度与真实跟踪，需要佩戴头显校准。
