# SimPy 网页参数 → Unity 完整联动验证

验证日期：2026-10-03。流程为 `C:/xjp/simpy2/3.csv` 的 79 道工序，Unity 工程为 `C:/AllUnityProjects/MainProject/MainProject`。

## 结论

已有工序编号和工位映射保持一致时，网页生产参数重新运行后能同步到 Unity：工位名称、状态、进度、AGV 流程运输时序、工作日时间以及装配／终检／完工数量均与发布的排产结果一致。

修改输入后必须点击“运行仿真”。输入框中的编辑本身不发布新结果；成功发布后 Unity 自动加载新运行，从月初开始回放。网页“月产量”是整个月的最终数量，Unity“本月已完工”是当前回放时刻的累计数量，两者在月底应一致。

不能把“所有可调项”理解为都会直接改变三维模型：网页布局和筛选只影响网页；设备资源数不复制设备模型；工序所属区域不自动搬动设备；新增、删除或改工序编号目前需要维护 Unity 映射。

## 验证方式与覆盖

- 14 次网页实际操作与运行记录：13 次参数／工序测试，以及一次最终恢复验证。通过真实输入框、勾选框、设备增删和 CSV 导入操作。
- 42 组独立接口参数场景，另加 5 组条件／边界场景及 1 组计算期间响应验证。接口使用网页相同的 `/api/simulation/run`，每次重新计算并由运行中的 Unity 正常 HTTP 轮询载入。
- 每组检查运行编号、全部 79 个工位的名称／区域／位置、完整事件的类型与起止时间、全部 AGV 路线与运输时间，以及采样时刻的工位状态、进度和并行数量。
- AGV 额外检查同一运输段的三个位置，确认发生实际移动；不是只检查路线 JSON。
- 在第一台真正完工的前后及月底，检查运行中的装配、终检、完工统计。
- VR 编辑器观看入口检查一组综合参数变更、一组 100% 返工场景和原始月底结果。检查共享时钟、只读角色、工位状态／进度／色值、AGV 位置和数量。头显未连接，不能视为 APK 真机验收。
- 对循环依赖、重复编号、空编号、缺失前置工序、空流程进行 5 组拒绝测试；对新增、删除、改编号进行映射边界测试。

覆盖所有生产输入字段及典型有效／无效值，不代表穷举所有数值和参数组合。测试记录读取真实运行状态；编辑器验证脚本不生成或替换播放事件。

## 动态展示检查

- 同一 AGV 运输段的三个实测位置分别为 `(13.43,-0.38,4.31)`、`(-6.30,-0.38,-11.39)`、`(-89.30,-0.38,2.82)`，与路线插值位置一致。
- 原始数据最早完工时刻为第 4621.503 仿真分钟。在前后各 0.25 分钟，Unity 完工数从 0→1；月底 10560 分钟为 5 台。
- 月末时间被限制在最后工作日的下班时刻，例如 22 天 × 8 小时显示“第22工作日 · 班内08:00”，不会显示成第23天。
- PC 最终状态在第 2950 分钟，显示“第7工作日 · 班内01:10”，此时实际完工数为 0，而网页最终月产量为 5；这是两种统计时刻的区别。
- VR 修改后的 6 小时 × 12 天显示“第12工作日 · 班内06:00”，原始月底显示“第22工作日 · 班内08:00”。VR 没有取得播放控制权。
- PC 和 VR 对活动工位的进度条与泛光 RGB 作了实测检查；加工为蓝、等待为黄、返工为紫，与事件状态一致。

AGV 目前演示发动机 1 的物流流程，不承担排产资源约束，也不表示每台产品都有独立 AGV。完整运输路线和时序能随参数改变，但没有实际移动工位时，通道的几何形状可以相同。

## 本轮修复的问题

1. 场景探针在 PC／VR 入口场景中只找到入口对象，会覆盖共享工厂探针并导致发布失败。现在查找已加载的共享工厂，未加载时保留有效探针并等待加载。
2. 网页此前仿真成功后不提示 Unity 发布失败。现在显示持续的失败提示，具体列出未绑定／已缺少的工序；成功运行后清除提示。
3. 循环依赖的失败结果此前被误报成功并发布成 0 台。现在验证循环、重复／空编号、缺失前置和空流程，失败不发布，不覆盖旧 Unity 结果。
4. 发布 CSV 的工具列表此前可能写成 Python 列表字符串。现在使用分号格式，并完成解析往返验证。
5. 无休息对比的质量数据结构不一致，以及百分比的零分母，造成 0%／NaN／Infinity。补齐质量数据，零分母显示明确说明；原始网页 0 次返工对比现在为 0.0%。
6. 排产计算原先阻塞服务事件循环，期间 PC／VR 时钟请求会超时。同步计算移入 FastAPI 的请求工作线程；一次约 5.96 秒的计算期间，15 次时钟读取全部成功，最慢约 0.30 秒。这是本机采样，不是网络或硬件性能保证。

长串测试中本地服务曾完全不响应，已重启同一 8000 服务，日志重定向到验证目录并关闭高频访问日志；卡住的具体原因未获得堆栈证据，不能仅凭恢复成功断言原因。
