# PT6A 29工位网页与Unity结果接通

网页计算排产，PC和VR展示同一份结果。场景沿用原厂房、设备、材质、工装、控制台、点击详情、漫游和VR导航；运行数据直接按网页的 `workstation_id` 对应 `WS-*` 物理工位。旧79工序编号仅作为原模型资源的兼容模板，不用于解释新工艺。

## 使用

本次按用户确认使用 **8001**，保留其他工具占用的8000服务。网页地址 `http://127.0.0.1:8001`；PC使用交付目录的“启动PC.cmd”，VR服务地址使用 `http://10.33.244.29:8001`。升级APK后若设备仍保留旧连接设置，请在原连接面板将端口改为8001。局域网地址变动后需在连接面板更新地址。

新浏览器会话可通过“文件 → 载入方案 JSON”打开交付目录 `data/网页269工步方案及原结果.json`，恢复原参数与已保存结果，无需重新运行仿真。随后在“结果分析 → 产出概览”的工位进度面板开启“跟随 Unity 时间”。载入方案本身不会切换活动结果。

1. 网页运行仿真后自动发布有效结果；浏览历史结果不会切换Unity。历史结果可点击工位进度面板中的“同步此结果到 Unity”。
2. PC启动后载入活动结果，从第0分钟暂停。原播放、暂停、时间拖动和倍速继续使用；VR只读跟随PC时钟。
3. 网页进度表默认仍显示期末。开启“跟随 Unity 时间”后每秒跟随PC；关闭后恢复独立查询。网页正在查看的结果与Unity结果编号不一致时，面板会显示两个编号，不混合采样。
4. 选择发动机后，工位环形进度表示该发动机在该工位已放行工步的标准工时占比。工位详情列出真实工步、当前事件及人员；全工位完成套数、在制数与个人工步执行进度分别显示。
5. 旧PC程序不支持新29工位协议，不能控制该模式的时钟。使用本次交付的PC程序和v17 APK；旧安装包保留。

第一次使用新版网页控件需刷新网页；请先保存编辑器中的未保存修改。

## 对应规则

- `sim_id` 标识同一次仿真，`publication_id` 为不可变快照的SHA-256。场景、时钟、进度和产量必须来自同一活动结果。
- 加工、等待、休息、返工、人员编号和事件起止时间来自网页真实甘特事件。期末被截断的未完成事件保留“进行中”状态，不计完成。
- 工位进度只累计实际放行工步的标准工时；执行中的部分工时、等待、休息和未通过的返工不增加完成进度。零时长尾工步未放行时，可以显示100%但仍未全部完成。
- 整机完工取网页 `engine_completion_events`，不再依赖旧A005/Q003/Q004编号。
- 原80个设备实例只负责展示。多工作台不增加仿真容量；同工位并行任务超出显示槽位时，全部真实记录仍保留在详情中。人员展示位置避开实体设备，统计人数仍取网页事件。
- 当前已确认的269工步基准结果为 `416d3475-f8d5-45dd-849c-97d69a5bb41c`，期末完成6台。场景支持动态工步数量，不将269写死。
- 最新270工步结果中的 `S270 → ST01` 没有对应物理工位。该结果及节点保留原样；同步会列出未映射项并保留上一个有效结果。需要在网页给该节点选择正确工位后重新仿真，程序不会自动归属或删除。

## 物流示意

AGV和吊车只演示真实跨工位依赖及工步放行后的配送；同工位交接和工位内S-Move不生成AGV运输。G01→G02→G03→G04→M05使用吊车，其他跨工位使用AGV。供给关系以网页输入流程为准，不补造缺失依赖。

默认展示第一台实际投产发动机的物流，随发动机筛选切换。复用原展示节奏，每段20个仿真分钟，取放各占该段前后8%；这不是正式运输耗时。运输候选、空车接驳和显示队列不会回写网页任务时间、资源约束、库存或产量。ST区域也不形成正式库存统计。

## 接口与缓存

| 接口 | 用途 |
|---|---|
| `GET /api/simulation/unity/active.json` | 活动模式、运行编号、时长、布局编号、快照地址和校验值；裸JSON |
| `GET /api/simulation/unity/runs/{publication_id}/replay.json` | 不可变schema 4快照，含真实流程、事件、放行时间线、完成事件及示意物流 |
| `POST /api/results/{sim_id}/publish-unity` | 显式发布历史结果；返回APIResponse |
| `GET /api/results/{sim_id}/station-progress` | 原工位采样接口，支持time_minutes、station_id、engine_id |
| `GET /api/simulation/unity/playback.json` | PC与VR共享回放时钟；网页跟随只读此接口 |
| 原播放claim/PUT接口 | 保留租约和版本冲突控制；新客户端提交mode=pt6a29，旧客户端默认legacy79 |

后端先生成、校验并保存完整快照，最后原子切换活动清单。未知工位、错误放行记录或写入失败不会替换活动结果。更换结果从0暂停，并释放旧控制租约；物理布局版本独立保留。

完整结果仅在切换发布版本时下载一次，之后在Unity本地采样。活动清单和时钟使用小请求轮询；HTTP大响应支持gzip。当前基准的物理布局仅需54组不同停靠点间的路线供所有示意运输复用。客户端缓存按服务地址及发布编号隔离，断线保留已载入数据并暂停，恢复后重新校验版本。旧schema 3回放及旧安装包继续保留。

## 验证记录

交付目录“检查与截图”保存编辑器与PC独立程序的逐时刻对照、路线检查、构建报告和截图。核对包括放行边界、未投产发动机、不同发动机筛选、时间回退、期末未完成、暂停、复位和倍速。

VR编辑器验证与头显实测分别记录；没有连接头显时，不将编辑器截图或APK构建成功当作头显实测。
